CHAPTER 01

What is a network?

A network is two or more devices connected so they can exchange data. Your phone, laptop, TV and printer at home form a local area network (LAN). The internet is a huge “network of networks”: millions of LANs joined together by routers owned by internet providers, companies and universities.

Messages are chopped upData travels in small pieces called packets. A photo becomes hundreds of packets that are put back together on arrival.
Every piece is labeledEach packet carries a source and destination address, like an envelope, so devices along the way know where it goes.
Rules make it workA protocol is an agreed set of rules. Both sides must speak the same protocol, the way two people need a shared language.

KEY IDEANetworks move labeled packets between devices using shared rules called protocols.

CHAPTER 02

The hardware and what each box does

Home routers often combine several of these jobs into one box, which is why the names get blurry. It helps to learn them separately.

EndpointLaptops, phones, printers and servers. They create and consume data. Each has a network interface card (NIC).
SwitchConnects wired devices in the same LAN and forwards frames only to the port that needs them, using MAC addresses.
Access pointA switch for radio. It bridges Wi-Fi devices onto the wired LAN.
RouterConnects different networks and picks the next hop toward a destination using IP addresses. At home it is your default gateway.
FirewallAllows or blocks traffic based on rules. Home routers include a basic one that blocks unsolicited inbound connections.
Modem / ISPConverts your provider’s line (cable, fiber, DSL, cellular) into Ethernet and hands traffic to the wider internet.

KEY IDEASwitches and access points connect devices within a network. Routers connect between networks.

CHAPTER 03

Addresses: MAC, IP, subnet and gateway

MAC address3c:22:fb:9a:10:4eA hardware ID on the network card. Used only on the local link, like a name tag inside one room.
IP address192.168.1.20A logical address that says which network you are on and which device you are. Used to route across networks, like a postal address.
Subnet mask / prefix255.255.255.0 = /24Splits an IP into a network part and a device part. With /24, the first three numbers name the network.
Default gateway192.168.1.1The router address. Anything not on your subnet is handed to the gateway to forward.

Private vs public

Home and office devices usually get private addresses (10.x.x.x, 172.16–31.x.x, 192.168.x.x) that are not reachable from the internet. Your router shares one public address for the whole house using NAT (network address translation). IPv6 offers so many addresses that every device can have its own globally routable one, with a firewall still deciding what may come in.

CHAPTER 04

Joining a network and finding names

DHCP: getting settings automatically

When a device connects it has no address yet. It broadcasts a request, and a DHCP server (usually your router) offers an IP address, subnet mask, gateway and DNS servers for a set lease time. The four messages are Discover, Offer, Request, Acknowledge, often remembered as “DORA.”

Watch DHCP in the Studio

DNS: turning names into addresses

People remember example.com; computers need an IP address. Your device asks a DNS resolver, which looks up the answer (or returns a cached one). Without DNS, a working network can still look “down” because nothing resolves.

Watch DNS in the Studio

KEY IDEADHCP gives a device its address. DNS turns names into addresses. Both happen before most apps send a single byte.

CHAPTER 05

Ports and protocols

An IP address gets data to the right device. A port number gets it to the right program on that device, like an apartment number. Transport protocols decide how the data is carried:

CHAPTER 06

Layers: why there are so many protocols

Instead of one giant protocol, networking is stacked in layers. Each layer does one job and relies on the layer below. The OSI model has seven layers and is mainly a teaching tool; the real internet follows the simpler four-layer TCP/IP model. Hover over the 1–7 numbers in the Network Studio header to see each one.

    Real protocols don’t always fit neatly into one layer. TLS, for example, is often described between transport and application.

    CHAPTER 07

    Putting it together: what happens when you open a website

    1. Join. Your laptop connects to Wi-Fi and gets an address, gateway and DNS server from DHCP.
    2. Look up. It asks DNS for the IP address of the site’s name.
    3. Decide where to send. The site is not on the local subnet, so the packet goes to the default gateway (the router).
    4. Translate. The router uses NAT to swap your private address for the home’s public address and sends it to the ISP.
    5. Connect. TCP (or QUIC) sets up a connection to port 443, and TLS encrypts it.
    6. Request and respond. HTTP asks for the page; the server sends it back through the same chain in reverse.

    Watch each step: DHCP DNS TCP TLS HTTPS

    CHAPTER 08

    Basic troubleshooting, bottom up

    Start at the bottom of the stack and work up. Most problems are found in the first three checks.

    1. Link. Is the cable plugged in, or is Wi-Fi connected? Are the lights on?
    2. Address. Does the device have the expected IP configuration? A 169.254.x.x IPv4 link-local address often means no usable DHCP lease was obtained.
    3. Gateway. Can you reach the router? If not, the problem is local.
    4. Internet by number. Can you reach a known public IP? If yes but names fail, it is DNS.
    5. Names. Does a lookup return an address? Try a different DNS resolver.
    6. The app itself. If everything else works, check the service, port, firewall or VPN.

    Useful built-in tools: ipconfig / ifconfig / ip addr to see your address, ping to test reachability, nslookup to test DNS, and tracert / traceroute to see the path. Only test networks you own or are allowed to use.

    Watch it: ICMP ping

    MODULE 09

    Wi-Fi is a link, not the whole internet

    A wireless device uses radio to reach an access point. From there, it uses the same IP addressing, routing, DNS and application protocols as a wired device. That distinction explains why a phone can say “connected” while websites, printers or casting still fail.

    AssociationJoin an access point advertising your chosen SSID. Device support, signal and authentication all matter.
    ConfigurationGet a usable address, prefix, gateway and resolver. Joining a radio network does not guarantee these settings are correct.
    ReachabilityCheck the actual destination. Guest isolation, routing, DNS or the service itself may limit access even with strong signal.

    Watch it: Wi-Fi association WPA3 authentication

    MODULE 10

    Make the network safer without breaking it

    Security is not a single switch. Protect device administration, encrypt sensitive traffic, keep software supported and limit which devices can reach each other. Start with the smallest set of permissions that lets the intended task work.

    EncryptionHTTPS, IPPS and VPN tunnels protect particular connections. Check where each protected connection starts and ends.
    Access controlAuthentication and firewall policy decide who may connect and what they may do. Encryption alone does not grant or restrict permissions.

    Watch it: TLS WireGuard

    SUBSECTION / SHARED DEVICES

    Networking printers and other shared devices

    THE #1 HELP-DESK TICKET

    Printers are the classic “it worked yesterday” device. They have their own IP address, advertise themselves on the network, and speak a few printing protocols. Once you understand those pieces, most printer problems become quick to solve.

    P1 / ConnectP2 / AddressP3 / DiscoverP4 / Print protocolsP5 / DriversP6 / SecureP7 / Fix “offline”P8 / Other devices

    P1

    Three ways to connect a printer

    EthernetMost reliable. Plug it into a switch or router port. Best for offices and busy printers.
    Wi-FiConvenient, but sleep modes, weak signal and guest-network separation can make it “disappear.”
    USB shared by a computerThe printer talks only to one computer, which shares it. If that computer is off, nobody can print.

    Many printers also offer Wi-Fi Direct, a small private network the printer creates itself so a phone can print without your main Wi-Fi.

    P2

    Give the printer an address that doesn’t move

    By default a printer gets its IP from DHCP, like any device. If the lease expires and it comes back with a different address, computers that saved the old address can no longer find it. Two fixes:

    DHCP reservation (recommended)In the router, tie the printer’s MAC address to one IP. The printer still uses DHCP, but always gets the same address. Easy to manage centrally.
    Static IP on the printerTyped into the printer’s menu. Works, but choose an address outside the DHCP pool to avoid two devices claiming the same IP.

    Watch it: DHCP leases

    P3

    How computers find printers automatically

    When you click “Add printer” and it just appears, the printer is advertising itself. These discovery messages are usually multicast, so they only reach devices on the same local network segment.

    mDNS + DNS-SD (Bonjour)The printer announces a name like office-printer.local and the services it offers. Used by Apple devices, most Linux systems, and modern Windows and Android.
    WSDWeb Services for Devices, a Microsoft discovery method common on Windows networks.
    Manual by IPWhen discovery is blocked, add the printer directly by its IP address. This is often the fastest fix.

    KEY IDEAIf a printer is on a different subnet or VLAN, it usually won’t appear automatically even though printing to its IP may still work.

    P4

    The protocols that actually print

    Printing protocols
    ProtocolPortNotes
    IPP / IPPS631 (TCP)Internet Printing Protocol, built on HTTP. Modern default. Reports status, ink and errors. IPPS adds TLS encryption.
    Raw / JetDirect9100 (TCP)Sends the print data straight to the printer with little status feedback. Simple and widely supported.
    LPD / LPR515 (TCP)An older Unix-era queue protocol. Still found on legacy systems.
    SMB445 (TCP)Used when a Windows computer or print server shares a printer.

    Related lessons: HTTP (IPP is built on it) TLS SMB

    P5

    Drivers vs driverless printing

    A driver translates your document into the printer’s own language. Drivers must match your operating system and are a common source of trouble. Most modern printers support driverless standards such as IPP Everywhere, AirPrint (Apple) and Mopria (Android and Windows), which use IPP and common formats such as PDF or PWG Raster so any compatible device can print without installing anything.

    Direct printing vs a print server

    At home, each computer prints directly to the printer. In larger offices, jobs go to a print server that manages queues, drivers, quotas and secure release. It adds control but becomes one more thing that must be running.

    P6

    Printers are computers too: secure them

    • Change the default admin password on the printer’s web page.
    • Install firmware updates from the manufacturer.
    • Turn off protocols you don’t use (for example FTP, Telnet, LPD or old SNMP versions).
    • Prefer encrypted options: IPPS and an HTTPS admin page.
    • Never expose a printer directly to the internet. Disable remote/cloud features you don’t need.
    • In offices, place printers and other IoT devices on their own VLAN or network segment, allowing only the traffic they need.
    • Wipe or remove stored jobs and storage before a printer is resold or recycled.

    P7

    Interactive: why does my printer say “offline”?

    Answer one question at a time. The checks follow the same bottom-up order as Chapter 08.

      P8

      The same ideas apply to other shared devices

      NAS / file storageShares files over SMB or NFS. Reserve its address, keep it updated and never port-forward its admin page.
      Smart TVs & castingDiscovered with mDNS/SSDP. Casting usually fails when the phone and TV are on different networks.
      IoT & smart homePlugs, bulbs and speakers. Often 2.4 GHz only. Put them on a separate IoT or guest network.
      CamerasChange default passwords, update firmware and avoid exposing them to the internet. Prefer local recording or a trusted service.

      REMEMBERStable address, working discovery, the right protocol, and sensible security. That checklist solves most shared-device problems.

              Seven layers, one useful mental model

              The OSI model separates responsibilities. Internet protocols do not always map one-to-one to its layers. The header highlights the lesson's primary teaching focus, not a claim that its entire exchange stays at one layer.

              1. PhysicalSignals, radio, electrical or optical links move bits.
              2. Data linkFrames and local-link delivery: Ethernet, Wi-Fi, MAC addresses.
              3. NetworkIP addressing and forwarding between networks.
              4. TransportEndpoint transport: TCP byte streams, UDP datagrams, QUIC transport.
              5. SessionConceptually organizes conversations and session lifetimes.
              6. PresentationConceptually represents data; encoding and cryptographic functions can span boundaries.
              7. ApplicationApplication exchanges such as HTTP, DNS, DHCP and email.

              A DHCP lesson still uses UDP, IP, link frames, and a physical medium. TLS is shown as a cross-layer security mechanism rather than a literal OSI presentation-layer implementation.

              Photos and recordings
              Raw pixels and PCM audio can contain structure a lossless compressor can exploit. PNG already uses lossless compression, so zipping a PNG often saves little. JPEG, MP3, and many video formats use specialized compression, often lossy; ZIP cannot restore details those formats already discarded.
              
                    
              Why not compress forever?
              No lossless compressor can make every possible input smaller: there are fewer short byte strings than long ones. Random-looking data often stays the same size or grows. Encryption normally removes useful visible patterns; compress before encrypting when appropriate, not to “undo” encryption.

                Lossless means reversible
                Decoding reproduces the exact original bytes. RLE expands count / value pairs. DEFLATE uses back-references and Huffman coding. Unlike lossy photo or audio encoding, neither deliberately discards information.
                
                
                ZIP is a container
                A ZIP bundles separate entries with filenames, metadata, and a central directory. Each entry can be compressed or stored. Metadata costs space, so tiny files can produce a larger archive even when their payload compresses.
                
                
                Integrity is not secrecy
                CRC-32 detects accidental corruption; it is not cryptographic authentication. Compression is not encryption. A ZIP from this lab is readable by anyone who receives it, and does not establish that its contents are safe.

                Encoding ≠ encryption
                Hex and Base64 change representation and need no secret to reverse. Hex uses two characters per byte. Compression exploits patterns; it does not keep data secret. Ciphertext is usually not usefully compressible.
                
                
                A hash needs trust, too
                A file hash helps detect changes if the expected digest came from a trusted source. Anyone can hash a message. Authenticating its sender needs something else, such as a keyed MAC or digital signature; this studio does not implement signatures.
                
                
                Authentication has limits
                An AES-GCM tag checks data using a shared secret key. It does not identify a person, prevent replay by itself, or solve key exchange. Real secure messaging needs a complete, reviewed protocol—not just an encryption function.
